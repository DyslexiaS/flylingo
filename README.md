# FlyLingo 飛語｜網站原型

FlyLingo 是菲律賓語言學校代辦。這個資料夾是給客戶看的**單檔網站原型**：每個 `.html` 都是獨立檔案，雙擊就能用瀏覽器打開，不需要伺服器。

產品要做什麼、不做什麼，寫在 [PRD.md](PRD.md)。

學校後台欄位寫在 [schema/school-fields.json](schema/school-fields.json)。中英文名稱、型態、選項、能不能篩選，以及 Excel 和現在頁面的對照，寫在 [schema/school-field-sheet.md](schema/school-field-sheet.md)。一筆是一個校區。

## 網站內容

單頁應用，網址用 `#` 切換頁面：

- `#home` 首頁：主視覺（右側是一張大照片，角落保留航線小圖）、三項服務、六間風格對照學校、城市照片區、諮詢時會先問的三件事、八步流程、常見問題搜尋、LINE 諮詢
  - 城市照片區是雜誌式排版，標題用思源宋。照片是城市風景，畫面上不寫出處；授權記錄在 `images/editorial/CREDITS.txt`
  - 首頁六間裡，宿霧和碧瑤的卡片會蓋上對應的城市風景，並標「城市風景」。學校自己的照片放進 `SCHOOL_PHOTOS` 之後，卡片會改用學校照片、拿掉這個標籤。克拉克的 CIP 目前沒有風景照，仍用城市插圖
- `#schools` 學校清單：43 個校區，可以搜尋，也可以依城市、課程、類型篩選。城市按鈕有各城市的插圖（`icons/region-*.svg`，打拉是稻田），選中時會換成該城市的顏色，有「清除條件」。一排三張卡片（手機一張），每頁 9 間，下方只顯示頁碼，選城市後標題會變成「克拉克 Clark」這種格式。卡片右上角是學校類型，有官方 IELTS／TOEIC 考場的學校會多一條藍色提示
- `#school/<id>` 學校詳情，由上往下：
  - 麵包屑「學校 › 城市 › 校名」：點城市會回到清單並自動篩選那個城市
  - 學校標題卡：城市方塊、校名、類型、官方考場；右上角「複製連結」可以把這間學校傳給朋友（手機版不顯示城市方塊，因為下面已有照片區）
  - **照片區**（標題卡下方）：大圖可左右翻（桌機有箭頭、手機用手指滑），左下顯示照片說明，右下「1 / 9」按下去會開全螢幕看圖。下面有分類按鈕（校園、教室、宿舍…，點了跳到那一類的第一張）和縮圖列；超過 6 張時最後一格顯示「+N」，點了看全部
    - 全螢幕看圖：鍵盤左右鍵翻頁、Esc 關閉，下方有全部縮圖
    - 也可以放 YouTube 影片：縮圖會自動抓 YouTube 封面並顯示播放鍵，點了直接在頁面上播放
    - 照片寫在 `_build_redesign.py` 的 `SCHOOL_PHOTOS`，用學校 id（網址 `#school/` 後面那段）對應。每張照片填 `src`（圖片網址）、`cat`（分類）、`caption`（說明）；影片把 `src` 換成 `video`（YouTube 網址）。檔案裡有範例
    - 還沒有照片的學校，先用城市插畫做成「校園外觀、教室、宿舍、餐廳、公共空間」五張示意圖，標示「照片整理中」
  - 「一眼看懂」三格：**管理強度**（5 格條，綠＝彈性、黃＝半斯巴達、珊瑚＝斯巴達）、**課程選擇**（ESL／雅思／多益／托福／商務／親子，有的打勾、沒有的劃掉）、**適合誰**
  - 分頁：簡介、課程（打勾清單）、住宿、設施、位置
  - **住宿**：「房型、住宿方式、洗衣清潔」每列前面有彩色插圖（`icons/school-*.svg`）。有列房型的學校（CIA、PILA、PINES、MONOL、Wales）會出現房型按鈕，點了會同步帶入右側詢問單；共同設備只列一次；沒列房型的學校會顯示「用 LINE 問這間」
  - **設施**：固定 11 格常見設施，分三種狀態：有（綠）、依校區（黃，資料寫「依校區」）、資料未提到（灰框）。有的排前面。灰色代表「我們的資料沒寫」，不一定是學校沒有。高爾夫、度假環境、兒童空間、Wi‑Fi 只在有提到時出現；對不上圖示的項目列在「其他」
  - 右側「幫我問這間」詢問單：點選想上的課、週數、房型，下方對話泡泡即時組出 LINE 訊息；按「複製訊息，開啟 LINE」會複製訊息並打開官方 LINE。學校官方聯絡資訊收在折疊區
  - 想讓 LINE 直接帶入訊息、不用貼上：在 `_build_redesign.py` 把 `LINE_OA_ID` 填成官方帳號 ID（例如 `"@flylingo"`）
- `#process` 和 `#process/<01-08>` 代辦流程：八步分成四個階段，每個階段一張白卡。每一步只有三樣東西：一句話說明、「你要做」（最多 4 項）、「完成後」拿到什麼。從首頁點某一步（例如 `#process/05`）會捲到那一步並短暫標亮
  - 流程文字寫在 `_build_redesign.py` 的 `PROCESS_STEPS`，會取代 `flylingo.html` 裡原本的流程資料（原本每步 8–13 項，含內部作業備註和跨步驟重複的內容）。首頁的八步摘要也讀同一份
- `#faq`、`#faq/<分類>`、`#faq?q=<關鍵字>` 常見問題：熱門問題、10 個分類、搜尋、可展開的問答
  - 問答寫在 `_build_redesign.py` 的 `FAQ`，會取代 `flylingo.html` 裡原本的範例回答。分類 `id`（`fit`、`cost`、`visa`…）不要改，首頁熱門問題和流程頁的連結都靠它。`volatile: True` 的分類（費用、簽證、出發）牽涉價格或政府規定，上線前要請顧問再確認
- `#blog` 部落格列表：第一篇是橫向大卡，其他兩欄排列。每張卡有主題插畫封面、分類、標題、摘要、閱讀時間
- `#article/<id>` 文章頁：標題卡（分類、標題、摘要、閱讀時間、封面），內文右側是「本篇目錄」，捲動時會標出目前讀到的段落（手機版目錄收在文章上方，可展開）。文末是 LINE 詢問框和「接著看」其他文章
  - **配合 WordPress**：文章內容只用 WordPress 編輯器本來就會產生的標籤，不需要任何自訂 class，樣式全部由網站負責：
    | WordPress 區塊 | 網站上看起來 |
    | --- | --- |
    | 標題（H2） | 段落標題，**自動變成目錄錨點** |
    | 段落、標題（H3） | 一般內文、小標 |
    | 清單 | 項目清單是綠點，編號清單是綠色數字圓圈 |
    | 表格 | 圓角表格，手機上可以左右滑 |
    | 引言 | 黃底「小提醒」框 |
    | 圖片（含說明文字） | 圓角圖片，說明文字置中 |
    | 詳細資訊（Details） | 可展開的常見問題 |
  - **目錄錨點**：每個 H2 自動得到 `sec-1`、`sec-2`…；如果在 WordPress 標題區塊的「HTML 錨點」填了名字，會優先用那個。可以分享直接跳到某一段的連結，例如 `#article/packing/sec-3`；文章裡原本就有的 `#錨點` 連結也會正常捲動
  - **圖片**：封面填 `cover`（WordPress 的精選圖片網址），沒填就用主題插畫；內文的圖片直接放在文章 HTML 裡
  - 文章資料寫在 `_build_redesign.py` 的 `ARTICLES`，欄位對應 WordPress：`title`＝標題、`excerpt`＝摘要、`kicker`＝分類、`cover`＝精選圖片、`html`＝文章內容。之後接 WordPress REST API 時，把 `content.rendered` 放進 `html` 就能直接顯示。封面插畫在 `BLOG_ART`，顏色用 `tone`（`mango`／`blue`／`coral`）

## 改版設計原則

1. **從左到右照使用者的注意順序排**：主要按鈕放左邊、次要放右邊；清單卡片先看校名，再看細節。
2. **用顏色分重點**：主題綠 `#3A7C30` 用在主要動作，芒果黃 `#FEC107` 用在重點標籤；流程裡「你要準備什麼」用淺黃底，因為那是使用者要做的事。
3. **淺灰底是 App 背景，白色是區塊**；陰影只用在需要強調的地方（主要按鈕、LINE 側欄、滑過的卡片）。
4. **能刪就刪**：拿掉每張卡片重複的「照片將使用學校授權素材」、多餘的說明句、重複的邊框；桌面版不放浮動 LINE 按鈕（頁首已有）。
   - **社群圖示**：桌面版放在頁首「LINE 諮詢」按鈕左邊（Threads、Instagram、Facebook，用各自的品牌色；LINE 已經有按鈕，不重複放）。手機版頁首沒空間，改放在頁尾，四個都有。連結和圖示只寫一次，在 `_build_redesign.py` 的 `SOCIAL_LINKS`，換網址改這裡就好。
5. **只顯示當下需要的**：學校官方聯絡資訊預設折疊；流程頁 8 個「用 LINE 詢問」大按鈕改成小文字連結。
6. **小而美的動態**：區塊捲到時淡入、卡片滑過時浮起、問答展開有動畫、頁首捲動後出現陰影。
   - V1 另外有：首頁主視覺是「台北 → 菲律賓」航線圖，捲到時虛線由台北畫出，星星沿著航線飛約 2 秒降落，接著跳出「直飛約 2–3 小時」標籤、終點閃兩次光圈（平板和手機寬度不顯示，避免把按鈕往下推）；手機版 LINE 按鈕出現兩次光圈提示。航線路徑是 `_build_redesign.py` 的 `ROUTE`。
   - V2 另外有：頁面頂端有捲動進度條、標題黃色螢光筆由左往右畫出、流星由左下飛入。
   - 學校詳情的管理強度條會一格一格長出來；流程展開清單時淡入。
   - 頁尾（兩版都有）：logo 右邊是標語「從語言出發，飛向世界。」和一句服務說明。捲到頁尾時，一顆芒果星沿著虛線從標語開頭飛到結尾降落，接著「飛向世界。」畫上黃色螢光筆，之後星星每隔幾秒閃一下；滑鼠移到這塊會再飛一次。手機版 logo 和標語改成上下排。
   - 如果使用者在系統設定開啟「減少動態效果」，所有動畫都會關閉。

## 文案原則（給工程與之後改文案的人）

全站文案在 `_build_redesign.py`：頁面文字在 `TEMPLATE`，流程在 `PROCESS_STEPS`，問答在 `FAQ`，文章在 `ARTICLES`。改完執行 `python3 _build_redesign.py`。

- **口吻**：台灣用語，稱使用者「你」，自稱「飛語」或「我們」。有活力但講具體的事，不用「最強」「保證」「一站式」這類誇大字。
- **只寫做得到的事**：例如寫「出發前會跟你確認接機時間」，不寫「全程無憂」。
- **固定用詞**，同一件事不要換說法：

| 用這個 | 不用 |
| --- | --- |
| 加 LINE 諮詢（主要按鈕）、用 LINE 問飛語（次要連結） | 聯繫客服、立即諮詢 |
| 校區（清單單位）、學校（泛稱） | 分校、據點 |
| 管理強度：自由彈性／偏彈性／半斯巴達／斯巴達／高強度斯巴達 | 嚴格度、管制等級 |
| 學校官方聯絡方式 | 學校窗口 |
| 資料整理中、照片整理中（還沒有資料時） | 待補、TBD |

## 色彩系統

所有顏色都定義在 `_build_redesign.py` 最上面的 `BRAND`、`NEUTRALS`、`ACCENTS`。網站和設計系統頁都從這裡讀，改一次兩邊都會更新。

| 角色 | 顏色 | 用在 |
| --- | --- | --- |
| 主色 | 飛語綠 `#3A7C30` | 按鈕、連結、選取狀態 |
| 輔色 | 芒果黃 `#FEC107` | 精選標籤、螢光筆、半斯巴達 |
| 強調（推薦） | 珊瑚橘 `#C84B2A` | 斯巴達、熱門、限時 |
| 強調（推薦） | 海洋藍 `#2A73AB` | 官方考場、認證、提示 |
| 強調（備選） | 蘭花紫 `#8459B3` | 親子、青少年 |
| 不建議 | 潟湖青 `#178278` | 太接近主色綠，不使用 |

城市插畫：學校卡片的照片區和詳情頁的城市方塊，不再是單色塊，而是該城市的線條插畫，顏色跟著城市走——宿霧（藍，海浪和椰子樹）、碧瑤（綠，松樹和山）、克拉克（黃，飛機和跑道）、克拉克／打拉（橄欖，丘陵和稻田）、馬尼拉（珊瑚，城市天際線和夕陽）。滑過卡片時插畫裡的太陽、雲、海浪或飛機會輕輕移動。插畫寫在 `_build_redesign.py` 的 `CITY_ART`，顏色在 CSS 的 `[data-city]`；新增城市時兩邊各加一筆，沒加的城市會先用宿霧的圖。

字體：全站統一用 `'Noto Sans TC', "微軟正黑體", "Work Sans", sans-serif, serif`（設定在 `_build_redesign.py` 的 `--sans`），Noto Sans TC 和 Work Sans 從 Google Fonts 載入。數字和英文城市名也用同一套字。

字級也在同一處，只用四種：頁面標題 `--fs-page`（28–38px）、標題 `--fs-sub`（18px，階段名和步驟名）、內文 `--fs-body`（16px，段落、按鈕、導覽、階段說明）、說明與標籤 `--fs-meta`（14px）。每級差 2px。14px 是最小可讀字，代辦頁的「你要做」和「完成後」用這一級。設計系統頁有一份對照。

每個強調色有三階：主色（放白字）、淡色底、深色字，全部通過 WCAG AA 對比 4.5。用量比例是中性 60%、綠 30%、黃加強調色 10%；按鈕永遠是綠色，一張卡片最多兩個強調色。

## 重新產生

```bash
python3 _build_redesign.py      # 從 flylingo.html 產生兩個改版和設計系統頁
```

`_build_flylingo.py` 需要 `~/Downloads/` 裡的兩份 Excel；其中「八大服務流程」那份目前不在電腦上。要改學校或流程資料，請先把 Excel 放回去，執行 `_build_flylingo.py` 更新 `flylingo.html`，再執行 `_build_redesign.py`。
